# Agent 任务派发清单

## product_manager — 提炼需求、确定范围、输出 PRD 与优先级
- 需求评审：功能缺口: 判断是否立项并把用户问题转为 PRD：用户明确表达功能缺口或新增能力需求
- 需求评审：价格与付费: 判断是否立项并把用户问题转为 PRD：用户对价格、会员或退款机制有疑虑
- 需求评审：性能与稳定性: 判断是否立项并把用户问题转为 PRD：用户遇到性能或稳定性问题
- 需求评审：易用性: 判断是否立项并把用户问题转为 PRD：用户在理解或操作路径上受阻
- 需求评审：客服与信任: 判断是否立项并把用户问题转为 PRD：用户对服务响应和可信度有担忧

## developer — 按 PRD 设计技术方案并实现最小可用功能
- 技术方案与实现：功能缺口: 基于产品经理确认范围实现最小可用方案
- 技术方案与实现：价格与付费: 基于产品经理确认范围实现最小可用方案
- 技术方案与实现：性能与稳定性: 基于产品经理确认范围实现最小可用方案
- 技术方案与实现：易用性: 基于产品经理确认范围实现最小可用方案
- 技术方案与实现：客服与信任: 基于产品经理确认范围实现最小可用方案

## tester — 设计测试用例、执行回归与边界验证
- 测试设计：功能缺口: 覆盖主流程、异常流程和回归风险
- 测试设计：价格与付费: 覆盖主流程、异常流程和回归风险
- 测试设计：性能与稳定性: 覆盖主流程、异常流程和回归风险
- 测试设计：易用性: 覆盖主流程、异常流程和回归风险
- 测试设计：客服与信任: 覆盖主流程、异常流程和回归风险

## acceptance — 根据业务目标和验收标准做最终验收
- 业务验收：功能缺口: 验证交付是否解决评论区暴露的真实问题
- 业务验收：价格与付费: 验证交付是否解决评论区暴露的真实问题
- 业务验收：性能与稳定性: 验证交付是否解决评论区暴露的真实问题
- 业务验收：易用性: 验证交付是否解决评论区暴露的真实问题
- 业务验收：客服与信任: 验证交付是否解决评论区暴露的真实问题
